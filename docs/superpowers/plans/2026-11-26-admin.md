# Admin (/admin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone-friendly `/admin` inside the Next.js app where allow-listed family members sign in with an emailed code and edit products (inline price/stock, full product form with photos, specs and rich description, product types), with changes live on the site immediately.

**Architecture:** Supabase Auth (email OTP) with cookie sessions via `@supabase/ssr`; `middleware.ts` gates `/admin/*`, and every Server Action re-checks the session and `ADMIN_EMAILS` before using the service-role client. Writes go through Server Actions; the full product save is one Postgres function (`admin_save_product`) so it is all-or-nothing. RLS makes the anon key read-only. Pure logic (slugs, prices, HTML sanitising, auth decisions, form seeding, audit diffs) lives in `lib/admin/*` with Vitest tests.

**Tech Stack:** Next.js 15.2.9 App Router, React 19, Supabase (`@supabase/supabase-js` 2.76, new `@supabase/ssr`), Tailwind 3, Vitest 3, zod 3, new: `sanitize-html`, `@tiptap/react` + `@tiptap/starter-kit` + `@tiptap/extension-link` + `@tiptap/extension-image`, `@dnd-kit/core` + `@dnd-kit/sortable`.

**Spec:** `docs/superpowers/specs/2026-11-26-admin-design.md`

## Global Constraints

- All admin UI copy in Vietnamese; sentence case.
- Every screen usable at 375px width; tap targets ≥ 44px.
- Status words: "Đang bán" = `published`, "Ẩn" = `draft`, "Lưu trữ" = `archived`. New products start as `draft`.
- No permanent delete anywhere in admin. Removing a photo deletes only the `product_images` row.
- `ADMIN_EMAILS` (comma-separated) lives only in `.env.local` and Vercel env — never in code, tests' fixtures use `@example.test` addresses.
- `SUPABASE_SERVICE_ROLE_KEY` is imported only from files with `import 'server-only'`.
- Every Server Action that writes calls `requireAdmin()` first and records an `admin_audit` row.
- After any product write: `revalidatePath('/', 'layout')`, `/products`, `/products/[slug]` (old and new slug), `/collection`, `/gallery`.
- Variants: only `option1_value` is edited ("Tên phiên bản"); `option1_name` kept, new variants get `'Phiên bản'`; `option2/3` untouched.
- Images: browser compresses to WebP, longest edge ≤ 2000px, quality 0.82; reject non-images and files > 20 MB; storage path `products/{product_id}/{uuid}.webp` in bucket `product-images`.
- Sanitised description allowlist: `p h2 h3 strong em ul ol li a[href] img[src,alt] br`; `href`/`src` must be `http:` or `https:`.
- `next.config` has `typescript.ignoreBuildErrors: true`, so every task's verification includes `npx tsc --noEmit -p . 2>&1 | grep -E "^(app|components|lib|middleware)"` → no output.
- Commit after each task; do not push. Applying the migration to the Supabase project and creating any auth user each need the user's explicit go-ahead in chat.

## Review Focus

1. Prices typed the Vietnamese way ("520.000", "520,000đ", " 1 200 000 ") → parsed to the right integer, never 520 or NaN — `parsePrice` tests in Task 1.
2. Session expires while a form is open → Save returns "Phiên đăng nhập đã hết hạn" and the form keeps everything typed — `withAdmin` test in Task 3.
3. Two people edit the same product → second save is refused with who/when, nothing overwritten — `isStale` tests in Task 4, conflict check in Task 6 browser verification.
4. iPhone photo the browser can't decode (HEIC in Chrome) or a 30 MB file → clear message, nothing uploaded — `imageProblem` tests in Task 7.
5. New product named like an existing one, or like a slug that now only exists as a redirect → gets `-2`, never collides — `uniqueSlug` tests in Task 1.

### Task 2: Database migration (written here, applied only with the user's go-ahead)

**Files:**
- Create: `supabase/migrations/003_admin.sql`, `docs/ADMIN_SETUP.md`

**Interfaces:**
- Produces (DB):

  - `product_variants.admin_edited_at timestamptz`

- [ ] **Step 1: Write the migration** (idempotent: `add column if not exists`, `create table if not exists`, `drop policy if exists` before `create policy`, `create or replace function`).

Policies: anon + authenticated `select` on `products` where `status = 'published'`; on `product_variants`/`product_images` where the parent product is published; `product_slug_redirects` select for all; no select on `admin_audit`. No insert/update/delete policies.

`admin_save_product(payload)`, `security definer`, `revoke all ... from public, anon, authenticated; grant execute ... to service_role`. Payload shape (matches `ProductFormValues` in Task 5 plus `id`, `expected_updated_at`, `email`):

```
{ id?: uuid, expected_updated_at?: timestamptz, email: text,
  product: { name_vi, slug, product_type, status, featured, excerpt_vi, description_vi, specs },
  variants: [{ id?: uuid, option1_value, price, compare_at_price, sku, inventory_quantity, track_inventory }],
  image_order: [uuid] }
```

Behaviour, in one transaction:
1. If `id` given: lock the row (`for update`); if `updated_at > expected_updated_at` → return `{"conflict": true, "updated_at": …}` without writing.
2. If slug changes: insert old slug into `product_slug_redirects` (`on conflict do nothing`); delete any redirect whose `old_slug` equals the new slug.
3. Upsert product (insert when no id), set `admin_edited_at = now()`.
4. Variants: update rows with id, insert rows without id (`option1_name` = existing first variant's or `'Phiên bản'`, `position` = array index), delete variants of this product whose id is not in the payload; set `admin_edited_at = now()` on written rows.
5. Images: `position` = index in `image_order`, `is_primary = (index = 0)`.
6. Return `{"id": …, "slug": …, "old_slug": …|null, "updated_at": …}`.
